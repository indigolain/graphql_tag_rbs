# GraphqlTagRbs

Generates [RBS](https://github.com/ruby/rbs) types for the GraphQL operations
in your Ruby code, so [Steep](https://github.com/soutaro/steep) can check how
you build variables and read responses.

It reads the operation list exported by
[graphql_tag_pluck](https://github.com/indigolain/graphql_tag_pluck) (0.3.0 or
later) and your GraphQL schema, and writes one `.rbs` file per Ruby source file.

## Usage

Given a heredoc in `app/clients/user_client.rb`:

```ruby
module Clients
  class UserClient
    USER_QUERY = <<~GRAPHQL
      query UserQuery($id: ID!) {
        user(id: $id) {
          id
          name
          role
        }
      }
    GRAPHQL
  end
end
```

run

```sh
bundle exec rake graphql_tag_pluck:generate_graphql_operation_list graphql_tag_rbs:generate
```

to get `sig/graphql/app/clients/user_client.rbs`:

```rbs
# Generated by graphql_tag_rbs from app/clients/user_client.rb. Do not edit.

module GraphQLTypes
  # query UserQuery at app/clients/user_client.rb:4 (Clients::UserClient::USER_QUERY)
  module UserQuery
    type variables = {
      "id" => ::String | ::Integer
    }

    type data = {
      "user" => {
        "id" => ::String,
        "name" => ::String?,
        "role" => ::GraphQLTypes::Enums::role
      }?
    }

    type response = {
      ?"data" => data?,
      ?"errors" => ::Array[::GraphQLTypes::error],
      ?"extensions" => ::Hash[::String, untyped]
    }
  end
end
```

and `sig/graphql/_shared.rbs` with the error type, enums (`type role = "ADMIN" | "MEMBER"`)
and input objects the operations use.

The types describe the parsed JSON response, so annotate where you parse it:

```ruby
# @type var response: GraphQLTypes::UserQuery::response
response = JSON.parse(http_response.body)
```

or give your client method a signature that takes `GraphQLTypes::UserQuery::variables`
and returns `GraphQLTypes::UserQuery::response`.

### Loading the rake task

In a Rails app the task is available automatically. In any other project, add this to your `Rakefile`:

```ruby
require "graphql_tag_rbs/rake_tasks"
```

## How GraphQL maps to RBS

| GraphQL | RBS |
|---|---|
| `String`, `ID` | `::String` |
| `Int` | `::Integer` |
| `Float` | `::Float` |
| `Boolean` | `bool` |
| custom scalar | `untyped`, unless mapped with the `scalars` option |
| enum | a literal union in `Enums`, e.g. `"ADMIN" \| "MEMBER"` |
| nullable field `T` | `T?` |
| list `[T!]!` | `::Array[T]` |
| field under `@include` / `@skip` | optional key, `?"field" => T` |
| union / interface | a record per distinct shape, with `"__typename"` as a literal type |
| fragment | inlined into each operation, plus a `data` type of its own |

Variables accept what GraphQL input coercion accepts: `ID` also takes `::Integer`,
`Float` also takes `::Integer`. Nullable variables and variables with a default value
are optional keys. Input objects become records in `Inputs`; `@oneOf` input objects
become a union of single-key records.

When a selection on a union or interface picks different fields for different
possible types, select `__typename` there. Generation fails otherwise, since
the result could not be told apart.

Each definition gets a module named after it (`query getUser` becomes `GetUser`).
Unnamed operations are skipped with a warning.

Operations are validated against the schema first, and errors name the operation
and where it is defined:

```
GraphQL validation failed:
  - UserQuery (app/clients/user_client.rb:4): Field 'nmae' doesn't exist on type 'User'
```

### Steep caveat

Steep reports calling methods on nullable fields and missing or mistyped variables,
but it does not report reading a key a record does not have: `user["nmae"]` is typed
as the union of the record's value types instead of an error.

## Configuration

Create `.graphqltagrbsconfig.yaml` to change any of these options:

- schema_path
  - The GraphQL schema, as SDL (`.graphql`, `.graphqls`) or an introspection result (`.json`)
  - default: `"schema.graphql"`
- input_path
  - The operation list exported by graphql_tag_pluck
  - default: `"__generated__/graphql_operation_list.json"`
- output_dir
  - Where to write the `.rbs` files. Generated files that are no longer produced are removed; files without the generated header are left alone.
  - default: `"sig/graphql"`
- namespace
  - The module the types are defined in. May be nested, e.g. `"MyApp::GraphQL"`.
  - default: `"GraphQLTypes"`
- key_style
  - `"string"` for `JSON.parse(body)`, `"symbol"` for `JSON.parse(body, symbolize_names: true)`
  - default: `"string"`
- scalars
  - RBS types for custom scalars, as they arrive in JSON
  - default: `{}`, e.g. `{ DateTime: "::String", JSON: "untyped" }`

Add the output directory to your `Steepfile`:

```ruby
target :app do
  signature "sig"
  check "app"
end
```
